# 07. AIツールからの接続認証

更新日: 2026-10-30
状態: 以下の初期仕様はユーザー合意済み。保存先のマイグレーションは実装・専用スキーマで検証済み。内部の発行処理も実装・実DB検証済み。照合・失効、API、画面、MCP接続は未実装。

## 学習と接続の境界

- 問題生成・出題・回答・判定・解説はユーザーのAIエージェント上で行う。スキル利用のためにWebログインや連携トークンの登録を要求しない。
- 学習中にアプリへ接続・保存せず、保存状態を通知しない。
- 学習後にユーザーが保存を選んだ場合、または保存済み記録の取得を選んだ場合に限り、接続を使う。
- Webの本人確認には既存GitHub OAuthを継続利用する。ユーザーへGitHubのPAT発行を求めない。連携トークンはLearning Companionが発行する。

## 合意済みの初期仕様

- Webにログインした本人が、接続名を付けてトークンを発行する。接続ごとに別のトークンを持てる。
- 有効期限は発行から30日間。使用による自動延長は行わない。
- 可能な操作は、本人の学習記録の保存・取得のみ。トークンによる設定変更・記録削除・別トークン発行は許可しない。
- トークン本体は発行時だけ表示し、接続ツール側の設定で管理する。スキル本文・学習内容・送信JSONに含めない。
- サーバーには照合用ハッシュだけを保存し、トークン本体は保存しない。
- APIはトークン照合・有効期限・失効状態を確認し、その所有者をuserIDにする。送信JSONから所有者を受け取らない。
- Webから本人が接続を個別に失効できる。無効・期限切れ・失効済みトークンでは保存・取得を実行しない。
- 期限切れ・失効後はWebで再発行し、接続設定を差し替える。ほかのトークンは個別に管理する。

## 実装順序

1. トークンの保存先と、発行・一覧・失効・照合の内部処理をTDDで作る。
2. 既存Web認証で保護したトークン管理APIと、トークン認証の入口を作る。別ユーザーによる操作を拒否する。
3. 発行・一覧・失効のWeb画面をつなぐ。トークン本体の再表示は行わない。
4. 学習記録APIとローカル接続ツールを接続し、本人の保存・取得を確認する。

これは作業順序であり、実装完了を示さない。具体的なテーブル名・APIパス・発行上限・画面・MCPの配布設定は実装前に整理する。

## 確認すること

- 学習のみならトークンなしで進められること（スキル実装時に確認）。
- 発行結果のトークンで本人を特定でき、DBには原本が残らないこと。
- 期限の直前は有効、期限ちょうど以降は無効となること。
- 失効した接続が使えず、別の接続は引き続き使えること。
- 別ユーザーのトークンを一覧・失効できないこと。
- トークンだけでは発行・管理や削除などの権限外操作ができないこと。
