# 06. 保持・削除・上限・公開条件（現行）

## 保持

保存済み教材、許可された会話、問題・回答・評価、復習履歴、選択した学習要点をユーザーが削除するまで保持する。
初期は自動削除期限を設けない。会話全ログを必ず保存する要件はない。

## 削除と失効

- PR単位の削除は、候補・学習セット・各回の問題・回答・判定・要点・会話・復習予定・通知対象・Storage本文を含む。
- アカウント削除は、全本人データ、設定、Webセッション、スキル接続認証を削除・失効する。
- 削除前に対象と復元不可を示し、最終確認する。
- 削除中・削除後の新たな保存、取得、復習通知を防ぐ。失敗時の後始末と再試行は詳細設計で定める。
- スキル接続は単独で解除できる。失効後は再送や再接続でも操作できない。
- 外部AIチャットや端末に渡したデータをアプリから削除できるとは案内しない。

## 利用上限

教材取得、保存リクエスト、会話・コード本文、保存容量、同時処理、通知回数に上限を設ける。
具体値は対応する実装前に決め、設定として管理する。旧案の数値を自動で採用しない。
外部AIの全実行回数や利用料金はサーバーから管理できないため、旧案の「LLM毎分10回制限」は採用しない。

## エラーと公開時の説明

- アプリが区別するのは、認証・失効、所有者違い、根拠・構造不正、上限、再送競合、保存・取得・通知失敗など。
- AI製品側の利用枠・ログインエラーはAIツール側の問題として案内する。サーバーが観測できない原因を断定しない。
- 公開PR限定、対象AIツールと必要な接続設定、AIに渡す教材、保存される内容、履歴の限界、削除・失効方法を説明する。
- WebのGitHub OAuthで利用を開始できる公開ベータを想定する。対象AIツールは最初は1つ。
- APIキー入力モーダルやOpenAI固定の送信同意文は作らない。教材を利用するAIツールと保存範囲に合わせて説明する。

## 受け入れ条件

- PR・アカウント削除後に対象データを取得できず、Storage削除と失敗時の後始末を確認できる。
- 削除・復習停止後の通知と、失効済み接続からの操作を防げる。
- 上限を超えた要求を実行せず、理由を表示する。
- 保存に失敗しても既存履歴を消さず、再試行で重複しない。
- 一連の公開条件は現行の要件定義と第二案に従う。旧BYOKのチェックリストをリリース条件にしない。
