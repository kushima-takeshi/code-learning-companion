# 03. スキルによる学習・回答・保存（現行）

## 目的と対象外

ユーザーのAIツール内で、手元のコード・差分・許可された会話を使い、候補選択から問題・回答・フィードバックまで進める。公開PR・元教材のアプリ保存を必須にしない。
GoからのAI呼び出し、AI APIキー入力、アプリ独自の回答・チャット画面は作らない。

## 接続と教材

- スキルはAIツールでユーザーの指定範囲を読み、認証付き接続で本人の学習記録を保存・取得する。教材取得APIの呼び出しを学習開始の必須手順にしない。
- 学習だけならWebログイン・連携トークン・アプリへの接続は不要。問題生成・回答・判定・解説までユーザーのAIエージェント上で進める。
- 学習後の保存、または保存済み記録の取得をユーザーが選んだ段階でのみ、アプリへの接続を案内する。
- AIツールからの保存・取得には、Webログインと別の期限付き連携トークンを使う。[接続認証の仕様](07-agent-connection.md)を参照。ローカルMCPアダプターの詳細は未実装。
- 元コードや会話全文はアプリへ自動送信しない。会話の全履歴を参照できるとは扱わず、本人の許可なく別プロジェクトの内容を混ぜない。
- 問題・回答・フィードバックにも非公開情報が含まれ得るため、送信前に内容を確認し、除外・一般化または保存中止できるようにする。AIツール内の読み取りとアプリへの送信を区別する。
- 一般化した記録を元の回答・評価そのものとして扱わない。確認方法、保存を除外した場合の進捗・復習対象の扱いは詳細設計で定める。

## 学習の手順

1. スキルがユーザーの指定した手元のコード・差分・会話等を読む。任意で保存済みPRも使える。
2. タイトル・説明・選定理由・根拠を持つ候補を最大3件提示する。候補のアプリ保存範囲は未決とし、元教材の保存を要求しない。
3. ユーザーが1件選ぶ。選ばなかった候補を強制しない。
4. AIエージェント上で2〜3問を生成する。選択肢・自由記述・小さなコード記述を扱う。アプリへの保存は出題の前提にしない。
5. 必要な最小限のコードを添えて1問ずつ出題し、回答を待つ。
6. AIエージェント上で回答を判定し、フィードバックを提示する。学習中はアプリへの保存処理を実行しない。学習後、ユーザーが保存する段階で送信内容を確認し、選んだ記録をアプリへ保存する。
7. アプリの履歴へ結果を反映する。別チャットでは保存済みの問題・回答・進捗から再開する。不足する元コードや会話はユーザーに再提示を依頼する。

根拠不足で候補が0件の場合、AI側の生成失敗、アプリ接続・保存失敗を区別する。学習中に保存処理・保存状態の通知を行わない。保存エラーは学習後に実際の保存操作を行った場合にのみ扱う。

## コード問題

- 本番ファイルと別の練習用ディレクトリに未完成コードを用意する。
- ユーザーが書き終わるまでAIが解答を実装しない。ヒントは依頼に応じて提示し、支援の有無を記録する。
- コード回答を保存する場合は送信を確認した提出時点の本文を残す。元のプロジェクト全体は送らない。ローカルパスだけをコード回答本文の代わりにしない。
- テストを使った場合は実行結果とAIの意味的評価を分ける。外部AIの実行報告はサーバーが独立検証した事実とは扱わない。

## 判定と解説

- 選択肢を含む回答の判定と解説はユーザーのAIエージェント上で行う。サーバーは受け取った学習記録の構造・関連・所有者を検証する。
- 理解度は「できた」「一部できた」「もう一度」「判定保留」。苦手理由・本人の自己評価は任意で別項目にする。
- 解説はできた点、不足点、根拠を示す。別解を文字列不一致だけで不正解にしない。
- 通信失敗は判定保留に置き換えない。判定保留時は回答修正や深掘りを案内する。
- 回答前のユーザー向け表示には正解を含めない。AIが解答情報を持つことと本人へ表示することを区別する。

## 保存と根拠

- 保存の中心は問題・回答・フィードバック、学習テーマ・関連・進捗・復習に必要な情報。保存済み教材IDやPR IDは必須にしない。
- スキルは読んだ根拠に基づき説明する。元教材を保存しなくても学習記録を保存できる。
- 保存済み教材への参照は任意。使用時は所有者、生成対象との一致、存在、範囲をサーバーで検証する。根拠のexcerpt本文は重複保存しない。
- 手元のパス・行番号等の出典情報は任意で、形式は未決。サーバーで原文を検証・表示できる参照とは区別する。原文がない場合、正しさを検証済みと表示しない。
- 学習後の保存段階で、ユーザーが選んだ問題・回答・フィードバックを保存する。保存対象の単位は詳細設計で決める。保存要求の単位では一部だけ保存した状態を作らない。
- 回答修正は新しい履歴、判定再試行は同じ回答。操作IDによる重複防止と競合検出を設計する。
- 判定・保存に失敗しても保存済み履歴を削除しない。実際に保存操作を行って失敗した場合だけ保存エラーを伝える。再送方法と未保存記録の保持方法は詳細設計で決め、チャット終了後も残るとは保証しない。
- アプリからの再開・復習予定は保存済みの問題・回答・フィードバック・進捗を基本とし、未保存内容を取得できるとは案内しない。
- 保存しなかった元コードや会話は復元できない。記録だけでは不足する場合、ユーザーに必要範囲の再提示を依頼し、推測で補わない。

## 最小保存入力の合意済みルール（2026-10-30）

以下は合意済みの契約。件数・容量・未知項目の検証は実装・テスト済み（1問・10問の保存・取得も実DB検証済み）。スキルの修正・再送手順は未実装。

- 1回の保存では問題・回答・フィードバックを1〜10問受け付ける。0問・11問以上は拒否する。スキルの出題目安2〜3問とは分ける。
- 送信JSON全体の上限は1 MiB（1,048,576バイト）。超過した場合は保存せずエラーにし、内容を自動で切り詰めない。
- 定義していないJSON項目は無視せず、保存前に拒否する。問題・回答・フィードバック内の項目も対象とする。最初に検出した未知の項目名を含む読み込みエラーを返す。
- JSONの読み込み失敗・容量超過・内容検証失敗では、空のSaveInputとエラーを返す。修正前の入力を部分的に保存しない。受信JSONはDecodeSaveInputを通してからSaveへ渡す。保存のHTTP入口は未実装のため、本文の読み込み自体の制限は保存API接続時に追加する。
- スキルは保存エラーを読み、決めた形式への修正後に再送できる手順を持つ。保存内容を削る変更が必要ならユーザーへ確認する。
- 修正・再送の回数に上限を設け、直せなければユーザーのAIチャットで保存できなかった理由を伝える。具体的な回数、エラー返却形式、修正可能なケースの詳細は未決。

## 学習記録一覧API（2026-11-01 実装・実DB検証済み）

接続先で本人の保存済み学習テーマを探す入口。新しい連携トークンによる接続確認にも使えるが、再接続の確認状態の記録・旧トークン失効との連携は未実装。保存・詳細取得API、MCP、履歴画面は後続。

- `GET /learning-records`。`Authorization: Bearer <連携トークン>`が必要。Webのsession Cookieだけでは利用できない。両方がある場合も連携トークンから所有者を決める。
- 応答は`{"records":[{"id":"記録のUUID","theme":"学習テーマ","created_at":"2026-11-01T03:00:00Z"}],"has_more":false}`。日時はRFC 3339形式。記録なし・末尾を超えた開始位置は200で`{"records":[],"has_more":false}`。
- 一覧では問題・回答・フィードバックの本文、所有者ID、要求ID、トークン情報を返さない。全件数も返さない。
- `limit`は省略時20、1〜100。`offset`は省略時0の非負の開始位置で、アプリ独自の最大値は設けない。`strconv.Atoi`でGoの`int`へ変換できる範囲を受け付ける（32ビット環境では32ビット、64ビット環境では64ビット）。これは表現上の制約であり、保存件数の上限ではない。ASCIIの数字のみ受け付ける。負数・符号・小数・空値・重複指定・変換できない値・未知項目・不正なクエリ文字列を拒否する。所有者を指定するクエリは受け付けない。
- `created_at DESC, id DESC`で並べ、指定件数より1件多く取得して`has_more`を判定する。続きは、同じ`limit`と`offset + recordsの件数`を指定して取得する。ページ間に追加・削除があると開始位置がずれ、重複・読み飛ばしが起こり得る。ページ横断のスナップショットや一括エクスポートは保証しない。
- ページ分割は件数・開始位置方式。特定AIツールに依存する契約ではなく、カーソル方式は今回採用していない。
- 認証をクエリ検証・一覧取得より先に行う。無効・期限切れ・失効済みトークンは同じ401。照合のDB障害は500として区別する。読み取りによる有効期限の延長は行わない。
- GETの成功・エラー応答はJSONで`Cache-Control: no-store`。401には`WWW-Authenticate: Bearer`を付ける。Go標準ルーターのGET登録によりHEADも同じ認証経路を通る。保存・更新・削除のルートは登録しない。

| HTTP | コード | 条件 |
|---|---|---|
| 400 | `invalid_pagination` | 件数・開始位置・クエリが契約外 |
| 401 | `unauthorized` | Bearerなし・複数Authorization・無効・期限切れ・失効済み |
| 500 | `internal_error` | トークン照合または一覧取得のDB障害等 |

エラー形式は`{"error":"コード"}`。原本・ハッシュ・SQL・DBエラー詳細は返さない。連携トークンはWeb認証のコンテキストへ変換せず、管理APIの権限を付与しない。実DBを使うHTTPテストで本人分離・0件・20/100件・続き・不正要求・認証拒否・DB障害・管理操作の拒否を確認した。

今回の件数上限は1応答内の行数制限。取得頻度・累積容量・レスポンスのバイト上限は別の設計事項として残す。通常開発DBへのマイグレーション5適用、実行中APIの再起動、ブラウザ・MCPからの操作確認は行っていない。

## 受け入れ条件

- 公開PRや元教材のアプリ保存なしで学習でき、本人認証したスキルが学習記録を保存・取得できる。他人の記録は取得・保存できない。
- 最大3候補から1件を選び、2〜3問を解き、保存を選んだ提出コード・回答・解説をアプリで見られる。
- 保存前に送信内容を確認・除外でき、元コードや会話全文を自動送信しない。
- 元教材未保存の記録を受け付け、保存済み教材を参照する場合だけ所有者・存在・範囲を検証する。
- 問題作成・出題・回答・判定・フィードバックの間は保存処理・保存状態の通知が発生しない。学習後に保存操作を行い、再送で重複せず、保存エラーでも既存記録は失われない。
- 初回チャットを閉じても保存済み記録から再開でき、不足する元教材の再提示を依頼できる。
- AI契約の認証情報をサーバーや教材に保存しない。
