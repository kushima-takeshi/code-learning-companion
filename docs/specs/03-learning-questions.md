# 03. スキルによる学習・回答・保存（現行）

## 目的と対象外

ユーザーのAIツール内で、保存済みPRと許可された会話を使い、候補選択から問題・回答・解説まで進める。
GoからのAI呼び出し、AI APIキー入力、アプリ独自の回答・チャット画面は作らない。

## 接続と教材

- スキルは認証付き接続で教材・履歴を取得し、結果を保存する。
- Webログインとは別に接続の本人認証と失効を設計する。MCPアダプター＋期限付きトークンは提案であり、確定前に実装しない。
- 現在の会話を根拠にする場合は必要箇所の保存を先に行う。会話の全履歴を参照できるとは扱わない。
- 原文と要約を区別し、会話と教材の関連を保存する。本人の許可なく別プロジェクトの内容を教材に混ぜない。

## 学習の手順

1. スキルが対象教材を取得する。
2. タイトル・説明・選定理由・根拠を持つ候補を最大3件作り、検証・保存する。
3. ユーザーが1件選ぶ。選ばなかった候補を強制しない。
4. 2〜3問を生成し、問題群をまとめて保存する。選択肢・自由記述・小さなコード記述を扱う。
5. 必要な最小限のコードを添えて1問ずつ出題し、回答を待つ。
6. 回答を保存してから判定・解説を作り、保存の成功を確認する。
7. アプリの履歴へ結果を反映する。別チャットでは未回答・未判定の場所から再開する。

根拠不足で候補が0件の場合と生成・接続失敗を区別する。

## コード問題

- 本番ファイルと別の練習用ディレクトリに未完成コードを用意する。
- ユーザーが書き終わるまでAIが解答を実装しない。ヒントは依頼に応じて提示し、支援の有無を記録する。
- 提出時のコード本文を保存する。ローカルパスだけを回答として残さない。
- テストを使った場合は実行結果とAIの意味的評価を分ける。外部AIの実行報告はサーバーが独立検証した事実とは扱わない。

## 判定と解説

- 選択肢の一致判定はサーバー、自由記述・コードの判定と解説はユーザーのAIが担当する。
- 理解度は「できた」「一部できた」「もう一度」「判定保留」。苦手理由・本人の自己評価は任意で別項目にする。
- 解説はできた点、不足点、根拠を示す。別解を文字列不一致だけで不正解にしない。
- 通信失敗は判定保留に置き換えない。判定保留時は回答修正や深掘りを案内する。
- 回答前のユーザー向け表示には正解を含めない。AIが解答情報を持つことと本人へ表示することを区別する。

## 保存と根拠

- 候補・問題・フィードバックは保存済み教材への根拠を持つ。場所だけ保存し、excerptを重複保存しない。
- 所有者、生成対象教材との一致、参照先の存在、行範囲をサーバーで検証する。意味的正しさを保証したとはしない。
- 根拠種別はPR本文、ファイル本文、差分、レビュー、保存した会話を想定する。JSON形式と行番号の仕様は順序1〜3で確定する。
- 問題セットと問題は一括確定し、一部だけ保存した状態を作らない。
- 回答修正は新しい履歴、判定再試行は同じ回答。操作IDによる重複防止と競合検出を設計する。
- 判定・保存に失敗しても既存履歴を削除しない。アプリから復元できる教材・問題・進捗を再開の正本とする。

## 未決事項

旧草案のpending/failed等を外部AIの状態へ無条件に当てはめない。

## 受け入れ条件

- 本人認証したスキルが自分の教材で出題し、他人の教材・回答を取得・保存できない。
- 最大3候補から1件を選び、2〜3問を解き、提出コードを含む回答と解説をアプリで見られる。
- 根拠を保存済み教材まで辿れる。不正な参照を拒否する。
- 回答後の通信失敗で回答が失われず、再送で重複しない。
- 初回チャットを閉じても、必要な文脈を取得して再開できる。
- AI契約の認証情報をサーバーや教材に保存しない。
