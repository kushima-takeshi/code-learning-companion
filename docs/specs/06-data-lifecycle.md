# 06. 保持・削除・上限・公開条件（現行）

## 保持

送信内容を確認して保存した問題・回答・フィードバック、復習履歴、選択した学習要点をユーザーが削除するまで保持する。
任意で取り込んだ公開PRや会話Markdownも保持対象とするが、元コードや会話全文は自動収集せず、学習の必須保存項目にしない。初期は自動削除期限を設けない。
本人限定の閲覧とサーバーへの送信は別であり、問題・回答・フィードバックにも非公開情報が含まれ得る。保存前に送信内容を確認・除外できるようにする。

## 削除と失効

- 学習セット単位で各回の問題・回答・判定・要点・復習予定・通知対象と対応する本文を削除できる。PR IDの存在を削除の条件にしない。
- 任意に取り込んだPRと添付会話・Storage本文も削除できる。PRと学習記録を関連付ける場合の削除範囲は実装前に定め、復習通知や利用不能な参照を残さない。
- アカウント削除は、全本人データ、設定、Webセッション、スキル接続認証を削除・失効する。
- 削除前に対象と復元不可を示し、最終確認する。
- 削除中・削除後の新たな保存、取得、復習通知を防ぐ。失敗時の後始末と再試行は詳細設計で定める。
- スキル接続は単独で解除できる。失効後は再送や再接続でも操作できない。
- 外部AIチャットや端末に渡したデータをアプリから削除できるとは案内しない。

## 利用上限

教材取得、保存リクエスト、会話・コード本文、保存容量、同時処理、通知回数に上限を設ける。
具体値は対応する実装前に決め、設定として管理する。旧案の数値を自動で採用しない。
外部AIの全実行回数や利用料金はサーバーから管理できないため、旧案の「LLM毎分10回制限」は採用しない。

## エラーと公開時の説明

- アプリが区別するのは、認証・失効、所有者違い、根拠・構造不正、上限、再送競合、保存・取得・通知失敗など。
- AI製品側の利用枠・ログインエラーはAIツール側の問題として案内する。サーバーが観測できない原因を断定しない。
- 公開PRなしでも学習できること、対象AIツールと必要な接続設定、AIツールで読む範囲、アプリへ送信・保存する範囲、履歴の限界、削除・失効方法を説明する。
- GitHubからの任意取り込みは公開PRのみ対応と説明する。これは手元の非公開コードでの学習を禁止する意味ではない。
- スキルの端末上での利用を、モデル推論の端末内完結とは説明しない。元教材を保存しない場合の復習・再開には再提示が必要になり得る。
- WebのGitHub OAuthで利用を開始できる公開ベータを想定する。対象AIツールは最初は1つ。
- APIキー入力モーダルやOpenAI固定の送信同意文は作らない。教材を利用するAIツールと保存範囲に合わせて説明する。

## 受け入れ条件

- PRに紐付かない学習セットも削除できる。学習セット・任意PR・アカウントの削除後に対象データを取得できず、対応するStorage削除と失敗時の後始末を確認できる。
- 削除・復習停止後の通知と、失効済み接続からの操作を防げる。
- 上限を超えた要求を実行せず、理由を表示する。
- 保存に失敗しても既存履歴を消さず、再試行で重複しない。
- 一連の公開条件は現行の要件定義と第二案に従う。旧BYOKのチェックリストをリリース条件にしない。
